# Decision vocabulary, v0

What the permanent record says when the policy said something finer than allow,
deny or escalate.

Vaara's gate offers five decisions: `ALLOW`, `DENY`, `MODIFY`, `STEP_UP` and
`DEFER`. A decision record carries three. That is not a shortcut, it is the
constraint: the verdict set is closed inside checkers published in this
repository for outside parties to run, so a record carrying a fourth word is
graded non-conforming by code already in other people's hands.

So the two extra names project onto the three, and these vectors are how a
stranger confirms the projection did what it claims rather than taking the
claim on trust.

## What is checked

Three rules, all recomputed from the exported bytes with nothing but a hash
function:

1. **The verdict is one of three.** `allow`, `deny`, `escalate`. Nothing else
   ever reaches a record.
2. **A refinement agrees with the verdict beside it.** `step_up` and `defer`
   are holds and record `escalate`. `modify` records `deny`, because the
   arguments it was asked about do not run. Proposed arguments appear only
   alongside a `modify`.
3. **A retry carries exactly the arguments the modify proposed.** Where a
   caller resubmitted, the resubmission's argument digest equals the digest of
   what the gate offered, so the second decision is bound to the bytes it
   actually decided.

Rule 3 is the one worth the vectors. The failure it rules out is a record
saying `allow` against arguments that were never the ones that ran, which reads
as clean evidence of something that did not happen. A `modify` blocks what it
was asked about and the retry is scored and recorded on its own, so no record
is ever bound to arguments other than its own.

The checker also recomputes every record hash and every chain link, which means
it reproduces Vaara's hashing path rather than trusting the committed hashes.

## Layout

```
cases/<name>.json       the exported audit records for one scenario
expected.json           the verdict each case must produce
_check_independent.py   stdlib only, no Vaara import
```

## The cases

Eight cases are what Vaara produces. They were generated by driving the real
pipeline, not written to match the checker.

| Case | What it is |
|---|---|
| `allow_plain` | a plain allow, no refinement |
| `deny_plain` | a plain deny |
| `escalate_plain` | a plain escalate |
| `step_up_hold` | `step_up` recording `escalate` |
| `defer_hold` | `defer` recording `escalate` |
| `modify_then_retry` | the full loop: blocked on the original arguments, allowed on the proposed ones, two decisions |
| `modify_without_modification` | a policy saying modify and supplying nothing, recorded as a plain deny |
| `contradictory_refinement_dropped` | a refinement that disagreed with its decision, refused at the recording boundary |

Five are what a gate **without** the projection would write. Four of them are
committed as non-conforming, so an outside party can confirm their checker
rejects them and not only that it accepts good records. The fifth,
`modify_without_retry`, is advisory and still conforms: it is there to pin the
line between a record that is wrong and a caller that simply stopped.

| Case | Rule it breaks |
|---|---|
| `verdict_outside_the_enum` | the refinement used as the verdict itself, which is what renaming `escalate` to `step_up` would have produced |
| `refinement_contradicts_verdict` | `allow` standing next to a `modify` |
| `retry_bound_to_other_arguments` | a retry claiming the modify as its parent while carrying the arguments the modify refused |
| `chain_break` | a decision reason edited after the fact, left unchained |
| `modify_without_retry` | a caller that never resubmitted. **Advisory**, and the case still conforms: giving up is allowed |

The four adversarial cases that are not `chain_break` are re-chained after the
mutation, so their hashes verify. They model an implementation that never had
the guard rather than a chain someone edited, which is the case the rules are
actually for.

## Regenerating

```
python scripts/build_decision_vocabulary_vectors.py          # rewrite
python scripts/build_decision_vocabulary_vectors.py --check  # fail on drift
```

Record ids and timestamps come from fixed sequences so the bytes are
reproducible. Every hash is computed by Vaara exactly as in production.
